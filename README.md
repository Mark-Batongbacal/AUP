# TUKI

TUKI is a mobile-first public transportation companion designed to help commuters plan, navigate, and manage trips using local transportation data, GPS navigation, and AI-assisted journey planning.

The project consists of an Android frontend, an ASP.NET Core backend, and a SQL Server database. The current implementation supports passenger trip planning and navigation, authentication, destination search, ride matching, driver workflows, and an AI assistant.

## Features

### 🗺️ Journey planning and route discovery

- Search for destinations and places using a location-aware search service.
- Plan journeys between an origin and destination.
- Generate persisted journey recommendations that can be selected and started as an active navigation session.
- Support route connections and transfers between transportation legs.
- Find nearby public transportation routes.
- Display route geometry, stops, route points, and transportation information.
- Support jeepney route data and tricycle pickup/connection points.
- Save frequently used trips as favorites and access recent trips.

### 🧭 Live navigation

- Start and restore an active journey.
- Track the commuter's GPS location during a trip.
- Provide turn-by-turn navigation instructions.
- Detect when the commuter is off route and trigger deterministic rerouting.
- Support explicit rerouting when needed.
- Track boarding and alighting states for individual transportation legs.
- Provide progress and distance information throughout the journey.
- Use landmarks as boarding, alighting, and route-progress references.
- Provide navigation speech/presentation text generated by the backend.

### 🤖 AI assistant

- Ask TUKI questions through the in-app AI assistant.
- Use an NVIDIA NIM-backed assistant service for AI requests.
- Extract journey-related intent from natural-language requests.
- Persist AI-generated journey plans so they can be used by the normal navigation flow.
- Provide AI-assisted navigation speech for supported navigation scenarios.

### 🔐 Authentication and accounts

- Local username/password authentication.
- Account registration.
- Google sign-in.
- Facebook sign-in, including Facebook OIDC support.
- Email verification.
- Password reset/recovery flow.
- Retrieve and update the authenticated user's profile.
- API-key-based authentication between the mobile client and backend.

### 🚗 Ride matching and driver features

- Create and manage passenger ride requests.
- Match passengers with available rides.
- Accept, reject, or cancel ride matches.
- Driver profiles and vehicle information.
- Driver availability sessions.
- Driver location updates.
- Support for driver-side transportation workflows through the backend API.

### 👤 User experience

- Onboarding flow.
- Home screen with trip and commute features.
- Destination search.
- Route results and commute details.
- Active trip tracking.
- Favorites and recent trips.
- Profile management.
- Settings.
- Map-based transportation and navigation views.

## Project layout

- `frontend/` — Android application built with Jetpack Compose.

## Run locally

### 1. Clone the repository

```powershell
git clone <repository-url>
cd AUP
```

### 2. Android frontend

Open `frontend/` in Android Studio, select an emulator or physical Android device, and run the `app` configuration.

For a Windows PowerShell build:

```powershell
cd frontend
.\gradlew.bat :app:assembleDebug
```

For macOS/Linux:

```bash
cd frontend
./gradlew :app:assembleDebug
```

### 3. Frontend configuration

Create or update `frontend/local.properties` with the values required by your local environment:

```properties
MAPS_API_KEY=YOUR_GOOGLE_MAPS_API_KEY
GOOGLE_SERVER_CLIENT_ID=YOUR_WEB_OR_SERVER_CLIENT_ID.apps.googleusercontent.com
BACKEND_BASE_URL=http://10.0.2.2:5129/
```

`10.0.2.2` allows an Android emulator to access the host machine's `localhost`.

For the deployed backend, use the configured production API URL instead.

### 4. Backend configuration

The backend loads local credentials from `backend/.env` when `ASPNETCORE_ENVIRONMENT=Development`. The file is ignored by Git.

Create `backend/.env` with your own values:

```text
Login__Users__0__UserName=admin@aup.edu
Login__Users__0__Password=<secure-password>
Login__Users__1__UserName=<second-user-name>
Login__Users__1__Password=<secure-password>
Login__Users__2__UserName=<third-user-name>
Login__Users__2__Password=<secure-password>
Login__Users__3__UserName=<fourth-user-name>
Login__Users__3__Password=<secure-password>
NVIDIA_API_KEY=<your-nvidia-api-key>
ConnectionStrings__TukiDbConnection=<sql-server-connection-string>
Valhalla__BaseUrl=<your-valhalla-base-url>
Pelias__BaseUrl=<your-pelias-base-url>
Facebook__AppId=<your-facebook-app-id>
Facebook__AppSecret=<your-facebook-app-secret>
```

Never commit real passwords, API keys, OAuth secrets, or database connection strings.

Start the backend in Windows PowerShell:

```powershell
cd backend
$env:ASPNETCORE_ENVIRONMENT = "Development"
dotnet run
```

On macOS/Linux:

```bash
cd backend
ASPNETCORE_ENVIRONMENT=Development dotnet run
```

The local API runs at `http://localhost:5129` by default.

### Health check

The public health endpoint does not require an API key:

```http
GET /health
```

The endpoint returns the server health status and response time.

## Production backend

The backend is currently deployed as a containerized ASP.NET Core service. The repository-root `Dockerfile` is used for the deployment build.

For container hosting such as Render or Azure Container Apps:

- Configure the required secrets as environment variables.
- Do not upload or mount the development `.env` file.
- Allow the platform-provided `PORT` environment variable to control the container listening port.
- Configure the SQL Server connection string and external service URLs in the deployment environment.

The Android frontend should point `BACKEND_BASE_URL` to the deployed API when testing against the production backend.

## Database

The backend uses the existing SQL Server database named `TukiDb` through Entity Framework Core.

The tracked database scripts are located in `database/`. Use the applicable schema/upgrade script when setting up or reconciling a local database. The application does not automatically modify the production database schema at startup.

## API

The mobile client communicates with the ASP.NET Core API using the `X-Api-Key` authentication header returned during authentication. The API contract is documented in [`frontend/API_CONTRACT.md`](frontend/API_CONTRACT.md).

The main mobile navigation flow is:

```text
POST /api/journeys/plan
        ↓
POST /api/navigation/start
        ↓
GET  /api/navigation/active
        ↓
POST /api/navigation/{sessionId}/location
        ↓
boarding / alighting / rerouting
        ↓
journey completion or cancellation
```

Other API areas include:

- Authentication and user profiles
- Places and destination search
- Routing and transportation routes
- Trip sessions
- Navigation and rerouting
- Favorite trips
- AI assistant
- Ride matching
- Driver availability and location
- Tricycle points
- Health monitoring

## Team branch workflow

Before starting work, update `dev`, switch to your own branch, and merge the latest development changes:

```powershell
git switch dev
git pull
git switch <your-branch>
git merge dev
```

For a new branch:

```powershell
git switch dev
git pull
git switch -c <your-branch>
```

Before committing:

```powershell
git status
git add <files-you-changed>
git commit -m "Describe your change"
git push -u origin <your-branch>
```

Keep secrets out of Git and verify that `.env` and local configuration files are not staged before pushing.

## Security notes

- Never commit `.env` files.
- Never commit production passwords, OAuth secrets, API keys, or database credentials.
- Store deployment secrets in the hosting provider's secret/environment-variable configuration.
- Keep Google Maps keys and other local frontend credentials in ignored local configuration files.
- API authentication is handled centrally by the frontend and enforced by the backend.
